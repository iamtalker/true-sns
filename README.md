# true sns

> 데이터는 사용자에게 있고, 서버는 서비스를 제공할 뿐이다.

하나의 범용 게시물(Nostr 이벤트)을 설정에 따라 **짧은 글 / 블로그 / 게시판**으로 다르게 보여 주고,
내 글은 **내 기기(로컬)가 원본**이며 언제든 **평범한 Markdown 파일**로 내보내고 가져올 수 있는 SNS.

- 현재 버전: **v0.5.1** (프로토타입)
- 저장소: [iamtalker/true-sns](https://github.com/iamtalker/true-sns) (비공개)
- 상세 설계, 발견한 문제, 로드맵: [DESIGN.md](DESIGN.md)

## 아이디어

1. **서비스가 아니라 표현 방식이 다르다.** 트위터, 게시판, 블로그는 같은 데이터(글, 작성자, 시간, 제목, 본문, 태그, 댓글)를 다르게 보여 줄 뿐이다.
2. **데이터는 사용자에게.** 원본은 사용자의 기기에 있고, 서버(릴레이)는 전달과 동기화만 맡는다. 서버가 사라져도 내 글은 남는다.
3. **내 글은 내 파일.** 언제든 Markdown(`.md`)으로 꺼내고, 다시 가져올 수 있다.
4. **신원은 키.** 공개키가 계정이고 게시물에는 전자서명이 붙는다. 서버를 바꿔도 정체성은 유지된다.

## 구조

```
┌ 표현 층 : 짧은 글 / 블로그 / 게시판 전환, 호스트 설정      ← 이 프로젝트에서 만든 부분
├ 소유 층 : 로컬 원본 + Markdown 입출력 + 폴더 자동 저장     ← 이 프로젝트에서 만든 부분
└ 전송 층 : 서명된 이벤트 + 릴레이 + 공개키 신원 (Nostr)     ← 기존 오픈소스 활용
```

| 폴더 | 내용 |
|---|---|
| `coracle/` | [Coracle](https://github.com/coracle-social/coracle)(MIT, © Jon Staab) 포크. 기준 커밋 `e4f46ebc0e29`. 추가한 코드는 가능한 한 `coracle/src/true/` 에 모았다. |
| `dev-relay/` | 로컬 테스트 전용 최소 Nostr 릴레이(메모리 저장). 운영에는 strfry 를 쓸 예정. |
| `start.bat` / `stop.bat` | 웹 앱과 테스트 릴레이를 켜고 끄는 스크립트 |
| `DESIGN.md` | 설계, 코드 분석, 발견한 문제, 로드맵 |

솔직히 말해 지금은 **Coracle 에 기능을 얹은 포크**다. 인증, 서명, 릴레이 통신, 피드, 설정 화면의 뼈대는 Coracle 것이다.

## 구현된 기능

### 소유 층
- **내 글은 지우지 않는다.** 로컬 저장소 정리 대상에서 내 글을 제외하고, 새 글은 배치를 기다리지 않고 즉시 저장한다.
- **로컬 우선 표시.** 피드가 네트워크 응답을 기다리지 않고 로컬 저장소의 내 글을 먼저 보여 준다.
- **Markdown 내보내기/가져오기.** 설정 → 데이터베이스 → 백업 만들기 / 백업 올리기.
  - 짧은 글은 `notes/`, 긴 글은 `articles/`, 제목·태그·식별자는 파일 맨 위(frontmatter)에 저장.
  - 가져온 `.md` 는 내 키로 서명되어 이 기기에 저장된다(릴레이로는 보내지 않음). 같은 식별자(`d`)는 새 버전으로 교체.
  - 기존 서명된 원본 백업(JSONL)도 유지.
- **폴더 자동 저장(일방향).** 폴더를 한 번 고르면 내 글이 평범한 `.md` 파일로 자동 반영된다.
  파일은 추가·갱신만 하고 삭제하지 않으며, 글을 고쳐도 같은 파일이 갱신된다. (Chromium 계열 브라우저 전용)

### 표현 층
세 모드는 같은 데이터를 다르게 보여 주고, 글쓰기 규칙도 다르다.

| | 짧은 글 | 블로그 | 게시판 |
|---|---|---|---|
| 목적 | 가볍게 던지는 글 | 한 사람의 글을 **읽기** | 여러 사람이 **토론** |
| 보이는 글 | 전부 | 제목 있는 긴 글만. 호스트에 `owner` 가 있으면 그 사람 글만 | 짧은 글 + 긴 글, 모든 작성자 |
| 목록 모양 | 카드 | 큰 제목 + 요약 + 날짜 + 읽는 시간 | 한 줄: 제목, 작성자, 날짜, 댓글 수 |
| 글쓰기 | 제목 없음, 280자 | 제목 필수 | 제목 필수 |

### 호스트 설정
서버 운영자가 앱과 같은 곳에 `true-host.json`(`coracle/public/true-host.json`)을 둔다.

```json
{ "name": "true sns", "mode": "micro | blog | board", "allowUserMode": true, "lang": "ko", "owner": "" }
```

| 항목 | 설명 |
|---|---|
| `mode` | 기본 모드 |
| `allowUserMode` | `false` 면 모드 전환 버튼이 사라지고 호스트 모드로 고정. `true` 면 사용자가 고른 모드가 우선 |
| `lang` | `ko` 또는 `en` |
| `owner` | 블로그 주인의 공개키(hex 또는 npub). 비우면 모든 작성자 |

파일이 없거나 값이 잘못돼도 항목별로 기본값을 쓰고 앱은 멈추지 않는다.

### 그 밖에
- **한국어 화면**: 영어 문구를 사전(`coracle/src/true/ko.ts`)으로 바꿔 주는 번역 층. 사전에 없는 문구는 영어로 남는다.
- **테스트 계정 버튼**: 로그인 화면의 "테스트 계정으로 입장 (개발용)". 개발 서버에서 `VITE_DEV_LOGIN=true` 일 때만 보이며 배포 빌드에는 나오지 않는다.
- **새 계정 릴레이 폴백**: 릴레이를 고르지 않은 새 계정도 호스트의 기본 릴레이로 발행된다.
- **홈 피드에 내 글 포함**, 발행 후 피드로 복귀, 글이 적을 때 아래 로딩 아이콘이 끝없이 도는 문제 수정.

## 실행 (Windows)

1. 처음 한 번만 의존성을 설치한다.
   ```bash
   cd coracle && pnpm install --ignore-scripts
   cd ../dev-relay && npm install
   ```
2. **`start.bat`** 더블클릭 → 웹 앱(`http://localhost:5173`)과 테스트 릴레이(`ws://localhost:7777`)가 각각 최소화된 창으로 뜨고 브라우저가 열린다.
3. 로그인 화면에서 **테스트 계정으로 입장**.
4. 끝낼 때는 **`stop.bat`** 더블클릭.

테스트 릴레이만 쓰도록 하려면 `coracle/.env`(git 에는 올라가지 않음)에 아래를 둔다. 이 상태에서는 공개 릴레이로 아무것도 나가지 않는다.

```
VITE_DEFAULT_RELAYS=ws://localhost:7777
VITE_INDEXER_RELAYS=ws://localhost:7777
VITE_SEARCH_RELAYS=ws://localhost:7777
VITE_DVM_RELAYS=ws://localhost:7777
VITE_SIGNER_RELAYS=ws://localhost:7777
VITE_ALLOW_LOCAL_RELAYS=true
VITE_DEV_LOGIN=true
```

기능을 눌러 볼 곳: 왼쪽 메뉴 **설정 → 데이터베이스**(`/settings/data`), 피드 위쪽의 **짧은 글 / 블로그 / 게시판** 버튼.

## 테스트

```bash
cd coracle && npx vitest --dir=tests/unit --watch=false   # 단위 테스트 31건
npx svelte-check --tsconfig ./tsconfig.json --threshold error
```

`svelte-check` 의 오류 1건(`nostr-signer-capacitor-plugin` 모듈 없음)은 아래 "알려진 한계"의 스텁 때문이며 웹 개발에는 영향이 없다.

## 알려진 한계

- **Android 전용 로그인 플러그인**(`nostr-signer-capacitor-plugin`)은 빌드 결과물이 없어 웹 개발용 스텁(`coracle/stubs/`)과 `vite.config.js` 의 alias 로 대체했다. **모바일 빌드 전에 제거해야 한다.**
- 폴더 자동 저장은 앱 → 폴더 방향만 된다. 폴더의 파일을 고쳐도 앱에는 반영되지 않는다(가져오기로 수동 반영).
- 블로그 글을 열면 아직 기존 Coracle 상세 화면이다. 게시판의 "최근 댓글순" 정렬과 페이지 나누기는 없다.
- 번역은 사전에 있는 문구만 바뀐다. 지갑, 초대 등 아직 열어 보지 않은 화면에는 영어가 남을 수 있다.
- 키를 잃으면 복구할 방법이 없다. 키 백업 안내 화면은 아직 없다.
- 테스트는 가짜 계정과 로컬 릴레이로만 했다. 실제 사용자의 Chrome 에서의 사용성은 충분히 확인되지 않았다.
- 서명된 글은 다른 릴레이에 퍼졌다면 완전히 지울 수 없다(삭제 요청만 가능). Nostr 의 구조적 한계다.
